## 프로젝트 대시보드 요구사항

### 원칙
- 전사의 진행 중 프로젝트를 한 화면에서 훑고, 위험한 프로젝트를 즉시 골라낼 수 있다.
- 정보 밀도를 우선한다 — 여백으로 프로젝트 수를 줄이지 않는다.
- 데스크톱에서 전체 목록을, 좁은 화면에서는 프로젝트별 요약으로 볼 수 있다.

### 전체 요약
- 전사 지표가 보인다: 진행 중 프로젝트 수, 위험 프로젝트 수, 전사 합산 수주금액, 전사 합산 현재 마진율.
- 위험(health) 등급별 프로젝트 개수가 보인다: 정상 / 주의 / 위험 각각의 집계.
- 인력 가동 요약이 보인다: 배정 인원 수, 벤치(미배정) 인원 수, 전사 가동률.

### 프로젝트 목록
- 각 프로젝트에 프로젝트명, 고객사, PM, lifecycle 상태(제안/진행/완료/중단)가 보인다.
- 각 프로젝트에 진척률(%)이 보인다.
- 각 프로젝트에 계획 기간과 실제 기간이 보이고, 실제가 계획을 초과하면 초과가 드러난다.
- 각 프로젝트에 투입 인원 수와 누적 투입 M/M가 보인다.
- 각 프로젝트에 수주금액과 현재 마진율이 보인다.
- 각 프로젝트에 health 신호등(정상/주의/위험)이 보인다.
- health는 마진과 진척을 종합한 결과이며, 무엇 때문에 주의·위험인지(저마진 / 일정 지연 / 적자)가 함께 드러난다.
- 프로젝트를 health 등급, 마진율, 진척률, 수주금액, 기간 기준으로 정렬해 볼 수 있다.
- 특정 health 등급, lifecycle 상태, 담당 PM, 고객사에 해당하는 프로젝트만 골라 볼 수 있다.
- 프로젝트명으로 검색할 수 있다.
- 한 프로젝트를 선택해 상세(프로젝트 손익 화면)로 이동할 수 있다.

### 위험 프로젝트 부각
- 위험·주의 프로젝트가 목록에서 먼저 눈에 띈다.
- 중단된 프로젝트는 종료 상태로 구분되어 보인다.
- 한 프로젝트의 적자가 전사 손익에 미치는 영향이 위험도에 비례해 드러난다.

### 가동 현황
- 벤치(미배정) 인력의 인원 수와 예상 벤치 비용이 보인다.
- 미배정 인력이 위험이 아닌 비용 신호로 절제되어 표현된다.
- 배정 대비 미배정 비율을 볼 수 있다.

### 주간보고 상태
- 각 프로젝트의 이번 주 주간보고 작성 여부가 보인다.
- 미작성 프로젝트가 누락 상태로 구분되어 보인다.
- 최근 보고된 진척·이슈 요약을 프로젝트에서 볼 수 있다.

### 민감 정보 제어
- 마진·손익·인건원가 등 민감 지표는 열람 권한이 있는 경우에만 값이 보인다.
- 권한이 없으면 해당 지표가 잠금 상태로 표시되고 값은 가려진다.
- 권한 없음은 위험 신호가 아니라 중립 상태로 표현된다.

## 실행 시 필수 고려사항

> plan-review 검토 중 발견한, 작업/TC로 환원되지 않는 서술형 전제. plan-run은 계획서만 읽으므로 여기에 명시한다.

### 스택·환경 전제 (환경 ②)
- 이 화면은 `plans/2026-07-06.PSA_MVP_프로토타입.md`가 정의한 **SvelteKit + adapter-static 정적 프로토타입**의 화면①(전사 포트폴리오 = 이 대시보드)이다. **DB·백엔드·외부 연동 없음** — 데이터는 `src/lib/data/mock.ts` 목업, 계산은 `src/lib/*.ts` 순수 함수.
- 단위 테스트는 **vitest**(순수 함수), 화면 동작 검증은 **Playwright e2e**(앱 기동 전제 → Z-post). DB 통합 테스트는 **해당 없음**(DB 미존재).
- `npm run check`/`build`/vitest는 `node_modules`가 gitignored이므로 워크트리에서 실행하지 않고 **머지 후 원본 main**에서 실행한다(Node 정적 게이트).

### 선행 의존성·파일 충돌·병렬 (환경 ③)
- **선행 전제**: MVP 스캐폴드 계획의 공통 산출물(`src/lib/types.ts`·`data/mock.ts`·`pnl.ts`·`format.ts`)이 존재해야 이 화면을 구현할 수 있다. 미존재 시 이 계획을 단독 실행할 수 없다 — MVP 스캐폴드가 선행되어야 한다.
- **pnl.ts 소유권**: `portfolioRollup`·`projectPnl`·`assignmentCost`는 **MVP 스캐폴드 계획이 소유**한다. 이 계획은 그것을 **import만** 하고 재정의하지 않는다. 대시보드 전용 파생 로직(health 종합·가동 집계)은 신규 `src/lib/health.ts`·`portfolio.ts`에 둔다.
- **공유 파일 `src/lib/permissions.ts`**: 권한 role store + 마스킹 헬퍼는 대시보드·손익 두 화면이 공유한다. plan-run에서 두 화면 계획을 병렬 실행하면 이 파일이 충돌한다 → **먼저 실행되는 계획이 생성, 뒤 계획은 재사용**하거나 두 계획을 직렬화한다.
- **화면 간 이동**: 대시보드 행 클릭 → `/project/[code]`(손익 화면)로 라우팅한다. 손익 라우트가 미존재해도 대시보드는 링크만 걸면 되고 렌더는 독립적이다 → 두 라우트 파일은 병렬 구현 가능.

### 회귀 (환경 ①)
- 이 대시보드의 **health 종합 등급(정상/주의/위험, 마진+진척)** 은 MVP 계획의 단순 **마진율 신호등(🟢≥30%/🟡15~30%/🔴<15%)** 을 대체·확장한다. MVP Verification의 "저마진 프로젝트 🔴 표시" 기대와 표기 체계가 달라질 수 있으므로, 마진 신호(색)와 health 신호(등급)를 **분리된 두 축**으로 유지한다(마진 신호는 손익 화면 소유, health는 대시보드 소유).

### 미확정 결정 근거 (환경 ④)
- **health 임계값**(저마진 기준 마진율%, 일정지연 판정식)·**전사 가동률 산식**·**권한 매트릭스**는 도메인 문서(`docs/2026-07-03_PSA-핵심-데이터모델-초안.md` §3·§4)에서 **미확정**이다. 프로토타입은 상수화된 **플레이스홀더 임계값**을 쓰고, 값 자체가 아니라 "자리(컬럼·신호)"를 확정하는 것이 목적이다. 임계값 상수는 한 곳(`health.ts` 상단)에 모아 교체 가능하게 둔다.
