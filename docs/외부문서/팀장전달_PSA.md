## 1. 이런 기능을 해주는 도구 리서칭

결론부터 말하면, 사용자가 말한 기능군은 **PSA, Professional Services Automation** 영역이 맞습니다. 일반 ERP는 회계, 인사, 구매, 급여 같은 회사 운영 중심이고, PSA는 **프로젝트 기반 서비스 사업**을 위해 견적, 인력 배정, 투입시간, 비용, 청구, 손익, 이슈를 프로젝트 단위로 연결하는 시스템입니다. SAP도 PSA를 “프로젝트 기반 서비스 제공을 위한 계획, 인력 배정, 시간/비용 추적, 청구, 수익성 관리” 영역으로 ERP와 구분합니다. ([SAP][1])

### 1-2. 리서칭 결과 해석

사용자 요구에는 **단순 프로젝트 관리 도구**가 맞지 않습니다. Jira, Redmine, OpenProject, Plane 같은 도구는 이슈/태스크 관리에는 적합하지만, 사용자가 원하는 핵심은 “프로젝트가 돈을 벌고 있는지, 앞으로 손실이 날지, 어느 계약/투입/이슈 때문에 마진이 깨지는지”입니다.

따라서 내부 개발 방향은 다음과 같이 잡는 것이 좋습니다.

> **메가존 내부용 PSA-lite 시스템**
> 프로젝트 단위로 영업검토, 견적, 계약, 인력계획, 투입실적, 비용, 매출, 이슈, 변경계약, 손익을 연결하고, AI는 문서 추출·위험 탐지·자연어 질의·요약을 담당한다.

중요한 점은 **AI가 손익을 계산하는 시스템으로 만들면 안 된다**는 것입니다. 손익, 마진, 투입률, 비용 계산은 반드시 DB 기준의 확정 수식으로 계산하고, AI는 다음 역할에 써야 합니다.

* 계약서, 제안서, SOW, 발주서에서 계약금액, 기간, 투입조건, 검수조건, 지체상금, 변경계약 조건 추출
* 과거 유사 프로젝트 기반 MM 산정 참고
* 프로젝트 위험 요약
* 주간보고 자동 생성
* “마진이 떨어진 이유” 자연어 질의
* 이슈/회의록에서 리스크와 액션아이템 자동 추출
* 예상 초과투입, 저마진, 인력부족, 청구지연 알림

## 2. 필수 요구사항 리스팅

### 2-1. 최상위 업무 흐름

사내 PSA는 최소한 아래 흐름을 하나의 프로젝트 코드로 연결해야 합니다.

```text
영업기회/수요 접수
 → 프로젝트 타당성 평가
 → 견적/제안/예상 손익
 → 내부 승인
 → 계약/발주/PO 등록
 → 프로젝트 생성
 → WBS/마일스톤/인력계획
 → 투입실적/비용 집계
 → 이슈/리스크/변경요청 관리
 → 매출/청구/검수 관리
 → 실제 손익/회고/지식화
```

핵심은 **프로젝트 코드 하나로 모든 데이터가 연결**되는 것입니다. 지금 엑셀 관리의 가장 큰 한계는 견적 파일, 계약 파일, 투입 인력표, 비용표, 이슈표, 주간보고가 분리되어 “현재 이 프로젝트가 정상인지”를 바로 알 수 없다는 점입니다.

### 2-3. 프로젝트 타당성 평가 요구사항

타당성 평가는 단순히 “매출이 얼마냐”가 아니라, **이 프로젝트를 수주해도 되는가**를 판단하는 단계입니다.

필수 입력값은 다음과 같습니다.

| 항목          | 설명                             |
| ----------- | ------------------------------ |
| 예상 계약금액     | 공급가액 기준, VAT 제외                |
| 예상 수행기간     | 시작일, 종료일, 총 개월 수               |
| 예상 투입 MM    | 역할/등급별 투입량                     |
| 내부 인력 가능 여부 | 해당 기간에 투입 가능한 인력 존재 여부         |
| 외주 필요 여부    | 외주 단가, 계약 가능성, 대체 가능성          |
| 솔루션/라이선스 비용 | 재판매/도입/구독 비용                   |
| 클라우드/인프라 비용 | Azure, AWS, Naver Cloud 등      |

| 리스크 버퍼      | 불확실성 비용. 예: 총원가의 5~15%         |

| 종합 Go/No-Go | 자동 추천 + 승인자 최종 판단     |

### 2-4. 계약 진행 관리 요구사항

계약 관리는 “계약서 파일 보관” 수준이면 부족합니다. PSA에서는 계약 데이터가 손익 계산과 연결되어야 합니다.

필수 관리 항목은 다음과 같습니다.

| 항목            | 필수 여부 | 설명                                   |

| 계약 상태         |    필수 | 제안중, 우선협상, 계약검토, 법무검토, 계약완료, 수행중, 종료 |
| 계약금액          |    필수 | 최초 계약금액, 변경계약금액 분리                   |

| 청구조건          |    필수 | 선금, 중도금, 잔금, 월정액, 마일스톤별 청구           |
| 검수조건          |    필수 | 산출물, 검수 기준, 검수 기한                    |

AI 적용 포인트는 명확합니다. 계약서나 SOW를 업로드하면 AI가 아래 필드를 자동 추출하고, 담당자가 검수 후 확정하는 방식이 좋습니다.

* 계약금액
* 계약기간
* 고객사/공급사

### 2-5. 프로젝트 매출 대비 투입 인력 수익률 요구사항

이 시스템의 핵심은 **프로젝트별 손익 원장**입니다.

최소 산식은 아래처럼 가져가야 합니다.

```text
계획 매출 = 최초 계약금액 + 확정 변경계약금액

계획 원가 =
  계획 내부 인건비
+ 계획 외주비
+ 계획 솔루션/라이선스비
+ 계획 클라우드/인프라비
+ 계획 출장/기타비
+ 리스크 버퍼

계획 마진율 =
  (계획 매출 - 계획 원가) / 계획 매출

실제 원가 =
  승인된 투입시간 × 내부 원가율
+ 확정 외주비
+ 실제 솔루션/인프라/기타비

예상 최종 원가, EAC =
  누적 실제 원가 + 잔여 계획 원가 + 추가 리스크 비용

예상 최종 마진율 =
  (예상 최종 매출 - 예상 최종 원가) / 예상 최종 매출
```

여기서 중요한 설계 포인트는 **개인 급여를 그대로 보여주면 안 된다**는 점입니다. 내부 시스템에서는 보통 다음 중 하나로 처리하는 것이 안전합니다.

| 방식          | 설명                         |
| ----------- | -------------------------- |
| 등급별 표준 원가율  | 초급/중급/고급/특급 또는 직급별 내부 원가율  |
| 조직별 평균 원가율  | 팀/직군별 평균 원가 사용             |
| 개인별 원가율 암호화 | 재무 권한자만 접근 가능              |
| 월별 원가율 스냅샷  | 과거 프로젝트 손익 재현을 위해 월별 단가 저장 |

대시보드에는 최소한 아래 지표가 필요합니다.

| 지표          | 설명                 |
| ----------- | ------------------ |
| 계획 매출       | 계약 기준 매출           |
| 실제/예상 매출    | 변경계약, 청구 가능성 반영    |
| 계획 원가       | 승인된 견적 기준          |
| 누적 실제 원가    | 현재까지 투입/비용 기준      |
| 잔여 예상 원가    | 남은 기간 인력계획 기준      |
| 계획 마진율      | 수주 당시 기준           |
| 현재 예상 마진율   | 오늘 기준 예상 최종 마진     |
| 마진 하락폭      | 계획 대비 현재 예상 마진 차이  |
| 투입률         | 계획 MM 대비 실제 MM     |
| Burn Rate   | 예산 소진 속도           |
| Overrun 예상일 | 현재 추세로 예산 초과 예상 시점 |
| 청구 지연 금액    | 수행했으나 청구/검수 지연된 금액 |

### 2-6. 이슈/리스크 관리 요구사항

이슈 관리는 단순 게시판이 아니라 손익과 연결되어야 합니다.

| 이슈 유형  | 예시                  | 손익 영향           |
| ------ | ------------------- | --------------- |
| 범위 증가  | 고객 추가 요청, 요구사항 변경   | 추가 MM, 변경계약 필요  |
| 일정 지연  | 고객 의사결정 지연, 개발 지연   | 인건비 증가, 지체상금 위험 |
| 인력 리스크 | 핵심 인력 이탈, 투입 지연     | 품질/일정/원가 악화     |
| 기술 리스크 | 신규 기술, 성능 문제, 보안 이슈 | 추가 투입, 외부 지원 필요 |
| 계약 리스크 | 검수 기준 불명확, 무상 범위 과다 | 청구 지연, 손실 가능    |
| 고객 리스크 | 담당자 변경, 의사결정 지연     | 일정/범위 변동        |
| 품질 리스크 | 장애, 재작업, 산출물 반려     | 추가 투입 발생        |

각 이슈에는 다음 필드가 필요합니다.

* 이슈 ID
* 프로젝트 코드
* 이슈 유형
* 심각도
* 발생일
* 담당자
* 조치기한
* 상태
* 예상 추가 MM
* 예상 추가 비용
* 변경계약 필요 여부
* 고객 귀책/자사 귀책/공동 귀책
* 의사결정 필요자
* 주간보고 포함 여부
* 관련 회의록/메일/계약 조항

AI는 회의록, 메일, 주간보고에서 이슈 후보를 추출하고, PM이 확정하는 방식이 좋습니다.

### 2-7. AI 기능 요구사항

AI 기능은 “있으면 좋은 챗봇”이 아니라 PSA 업무 흐름에 붙어야 합니다.

| AI 기능        | 설명                                                  | 우선순위 |
| ------------ | --------------------------------------------------- | ---: |
| 자연어 질의       | “이번 달 마진 10% 미만 프로젝트 보여줘”, “A고객 프로젝트 손익 악화 원인 요약해줘” |   높음 |
| 계약서/SOW 추출   | 계약금액, 기간, 검수, 청구조건, 지체상금 자동 추출                      |   높음 |
| 유사 프로젝트 추천   | 과거 유사 프로젝트의 투입 MM, 이슈, 최종 마진 참고                     |   높음 |
| 타당성 평가 보조    | 견적 누락, 과소산정, 리스크 항목 추천                              |   높음 |
| 이슈 자동 추출     | 회의록/메일에서 리스크, 액션아이템, 변경요청 추출                        |   높음 |
| 주간보고 자동 생성   | 프로젝트 상태, 이슈, 손익, 일정 기반 보고 초안 생성                     |   중간 |
| 마진 하락 원인 분석  | 계획 대비 실제 투입 증가, CR 미반영, 청구 지연 등 원인 설명               |   높음 |
| 알림/경보        | 저마진, 초과투입, 청구지연, 인력공백 사전 탐지                         |   높음 |
| 문서 RAG       | 계약서, 제안서, 회의록, 산출물 기반 질의응답                          |   중간 |
| PM Assistant | 다음 액션 추천, 승인 필요사항 추천                                |   중간 |

단, AI 결과는 반드시 다음 구조여야 합니다.

```text
AI 추천/요약
 → 근거 데이터 표시
 → 담당자 검토
 → 확정 저장
 → 감사 이력 보관
```

AI가 바로 계약금액, 손익, 승인 상태를 확정하면 안 됩니다.

### 2-9. 연동 요구사항

사내 개발 시 모든 기능을 처음부터 만들 필요는 없습니다. 핵심은 **프로젝트 원장**을 만들고, 기존 시스템 데이터를 끌어와 연결하는 것입니다.

| 연동 대상                 | 가져올 데이터                  |
| --------------------- | ------------------------ |
| ERP/회계                | 매출, 청구, 수금, 비용, 외주비      |
| HR/인사                 | 직원, 조직, 직급, 재직상태, 휴가/가용일 |
| 그룹웨어/결재               | 계약 승인, 견적 승인, 변경계약 승인    |
| Jira/Redmine/GitLab 등 | 이슈, 태스크, 작업로그, 개발 진행률    |
| 메일/문서함                | 계약서, SOW, 제안서, 회의록       |
| 근태/타임시트               | 실제 투입시간                  |
| CRM/Sales 관리          | 영업기회, 고객사, 제안 상태         |
| 클라우드 비용 시스템           | 프로젝트별 클라우드 사용료           |

가장 먼저 필요한 것은 **프로젝트 코드 표준화**입니다. ERP, Jira, 문서, 결재, 엑셀, 타임시트에 같은 프로젝트 코드가 없으면 통합은 계속 실패합니다.

## 제안: 메가존 내부용 PSA-lite로 시작

처음부터 Certinia나 Dynamics 365 Project Operations 같은 전체 PSA를 복제하려고 하면 범위가 너무 큽니다. 우선순위는 아래처럼 잡는 것이 현실적입니다.

### 1단계 MVP

| 범위       | 구현 내용                            |
| -------- | -------------------------------- |
| 프로젝트 마스터 | 프로젝트 코드, 고객사, PM, 영업, 상태, 기간     |
| 타당성 평가   | 예상 매출, 예상 원가, 예상 마진, 리스크 점수      |
| 견적 버전관리  | 역할/등급별 MM, 단가, 비용, 마진            |
| 계약 등록    | 계약금액, 기간, 청구조건, 계약서 첨부           |
| 인력계획     | 월별/주별 투입계획                       |
| 투입실적     | 엑셀 또는 기존 근태/타임시트 업로드             |
| 손익 대시보드  | 계획 대비 실제, 예상 최종 마진               |
| 이슈/CR 관리 | 추가 투입, 변경계약 필요 여부                |
| AI 질의    | “위험 프로젝트”, “마진 하락 원인”, “이번 주 보고” |

### 2단계

| 범위          | 구현 내용                   |
| ----------- | ----------------------- |
| 계약서 AI 추출   | SOW/계약서에서 주요 조건 자동 추출   |
| 유사 프로젝트 분석  | 과거 프로젝트 기반 예상 MM/리스크 추천 |
| 주간보고 자동화    | 프로젝트 상태 보고서 자동 생성       |
| 승인 워크플로우    | 저마진, 변경계약, 추가투입 승인      |
| Jira/ERP 연동 | 이슈, 실적, 비용 자동 수집        |

### 3단계

| 범위       | 구현 내용                     |
| -------- | ------------------------- |
| 리소스 최적화  | 인력 가용률, 스킬, 투입 충돌 자동 분석   |
| 손익 예측    | EAC, 예상 최종마진, 손실 가능성 예측   |
| 포트폴리오 경영 | 고객/조직/PM/산업별 수익성 분석       |
| AI 에이전트  | 계약검토, 리스크탐지, 보고서생성, 액션 추천 |

최종적으로는 **“프로젝트 단위 관리”가 아니라 “서비스 사업 손익 운영 시스템”**으로 봐야 합니다. 메가존 내부에서 먼저 만들 경우, 핵심 성공 기준은 기능 개수가 아니라 다음 5가지입니다.

1. 프로젝트별 예상 마진과 실제 마진을 한 화면에서 볼 수 있는가
2. 투입 인력 증가가 손익에 즉시 반영되는가
3. 계약/변경계약/청구조건이 프로젝트 손익과 연결되는가
4. 이슈가 추가 MM, 추가 비용, 변경계약 필요 여부로 연결되는가
5. 경영진/팀장/PM이 자연어로 “어떤 프로젝트가 위험한지” 물어볼 수 있는가
