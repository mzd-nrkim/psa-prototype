# 사내 PSA(가칭) — 보고 1페이지

> 작성 2026-07-03 · 성격: **재설득이 아니라 보고** (본 아이디어는 팀장 제안). 아이디어를 한 단계 구체화해 공유하고, 결정이 필요한 지점을 위로 올리는 문서.

## 1. 배경

- 현재 사내 핵심 항목(계약·정규직/계약직·등급·멘먼스·손익계산서·프로젝트 진척)을 **엑셀로 관리** → 불편·중복입력·실수·권한통제 부재.
- 이를 **사내 전용 웹 서비스**로 만들자는 제안.

## 2. 제안 — "사내 PSA(프로젝트 경제성 레이어)"

이 카테고리의 정식 명칭은 **PSA(Professional Services Automation)**. 핵심은 **더존(인건비/원가)과 Salesforce(계약/매출)를 이어, 두 시스템 다 안 해주는 "프로젝트별 손익·인력 투입"을 한눈에 보여주는 레이어**다.

**이 툴이 하는 것**
- 프로젝트별 손익 (수주금액 − 투입 인건원가 = 마진)
- 임직원별 투입·기여
- 전사 손익계산서 롤업
- 주간업무보고 = **리스크 뷰어** (진척률·이슈)
- 대시보드: 프로젝트별 [진척률·실제기간·투입인원·수주금액·마진] 한눈에

**이 툴이 하지 않는 것 (범위 명확화)**
- WBS 수준의 상세 일정관리 ❌ (요구 아님)
- 급여 계산 자체 ❌ (더존이 SoT)
- 계약/PO 관리 자체 ❌ (Salesforce가 SoT)

## 3. 왜 사내 구축인가 (사서 안 쓰고)

- 상용 PSA(Scoro·Kantata·Certinia 등)는 성숙하지만, **인당 수익·급여파생 원가는 최고 민감 데이터**라 외부 SaaS 반출이 부담.
- 우리 등급체계·멘먼스 원가산정 룰을 **하드코딩**할 수 있어 fit이 좋음.
- 더존+Salesforce **커스텀 연동**이 어차피 필요.
- 참고: 더존 iCUBE에도 "프로젝트별 손익" 기능이 있을 수 있어 **확인 필요** (있으면 우리 범위 축소 가능 — 정직하게 체크).

## 4. 이전 프로젝트(lodestar) 자산 승계 — "처음부터 다시" 아님

- 기술 스택(FastAPI + SvelteKit + Postgres + Docker) **그대로 재활용**.
- lodestar의 "리스크 뷰/캔버스" 작업물 → **주간보고 리스크 뷰어**로 전용 가능.
- 즉 방향만 트는 피벗이라 매몰비용이 작다.

## 5. 결정이 필요한 지점 (위로 올림)

| 항목 | 필요한 결정 | 결정 주체 |
|---|---|---|
| 권한 모델 | 인당 수익·급여를 누가 열람? | **경영/인사(윗선)** |
| 데이터 민감도 | 급여 원본 vs 등급단가만 사용 | 윗선 |
| 더존 연동 | 제품명·손익기능 유무·반출 방식 | 경영지원/정보시스템 |
| SF 연동 | 계약/PO 데이터 공유 가능 여부 | 계약팀 |
