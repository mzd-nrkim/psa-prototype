# PSA MVP 프로토타입 — 임원 발표용 동작 데모

사내 PSA(프로젝트 경제성 레이어)의 핵심 가치인 **"이 프로젝트 남는 장사인가"**를 임원에게 증명하기 위한 **동작 프로토타입**을 만든다. 더존/Salesforce 연동은 범위 밖(확정)이며, 급여 원본도 쓰지 않는다. DB·백엔드 없이 SvelteKit 정적 앱 + JSON 목업 데이터로 3개 화면을 구현해, 5분 데모로 "흩어진 엑셀 → 한 화면, 위험 프로젝트 빨간불 → 원인 드릴다운 → 인력 관점"을 보여준다.

이 프로토타입은 제품이 아니라 **설득 자산**이다. 실제 등급체계·단가·프로젝트 데이터는 미확인이므로, 그럴듯한 플레이스홀더 값을 박아 "자리(컬럼)"를 확정하는 것이 목적이다.

---

## 목표

- 4개 핵심 엔티티(Project·Employee·Grade·Assignment)와 1개 파생 뷰(ProjectPnL)의 **컬럼이 예시 데이터로 채워진 상태**로 확정된다.
- 임원 발표용 **3개 화면**(전사 포트폴리오 / 프로젝트 손익 상세 / 임직원 투입 현황)이 브라우저에서 동작한다.
- 마진(수주 − Σ배정원가)이 **하드코딩이 아니라 목업 데이터로부터 자동 계산**되어, 배정을 바꾸면 마진이 갱신되는 것을 시연할 수 있다.
- 급여 원본 없이 **등급 표준원가율만** 사용하는 원가 산정 구조가 코드로 구현된다.
- DB·백엔드·외부 연동 **없이** 정적 배포 가능한 형태(로컬 `npm run dev` 또는 정적 빌드)로 완성된다.

## 접근 방법

1. **greenfield 스캐폴딩**: `psa_private` 루트에 SvelteKit(정적 어댑터) 프로젝트를 생성한다. lodestar에서 언급된 스택(SvelteKit)을 승계하되, 데모 목적상 Postgres·FastAPI·Docker는 도입하지 않는다. `adapter-static`로 백엔드 없이 배포 가능하게 한다.

2. **데이터 계층 = 단일 JSON 목업 + 파생 계산 모듈**:
   - `src/lib/data/mock.json`(또는 `.ts`)에 Grade·Employee·Project·Assignment 예시 레코드를 담는다.
   - `src/lib/pnl.ts`에 파생 계산 순수 함수를 둔다: `assignmentCost(assignment, grade)` = 등급 표준원가 × M/M, `projectPnl(project, assignments, grades)` = 수주 − Σ배정원가 → {매출, 배정원가합, 마진, 마진율}, `portfolioRollup(projects)` = 전사 합계·마진율.
   - 계산은 전부 이 모듈에 격리해 **단위 테스트 대상**으로 삼는다(손익 로직이 프로토타입의 신뢰 핵심).

3. **3개 라우트 구성**:
   - `/` (전사 포트폴리오): 프로젝트 테이블 + 마진율 신호등(🟢≥30% / 🟡15~30% / 🔴<15%) + 전사 합계 행. 행 클릭 → 상세로 이동.
   - `/project/[code]` (프로젝트 손익 상세): 배정 원장 테이블(직원·등급·M/M·산정원가) + 매출−원가=마진 브레이크다운 + 저마진 경고 문구. 배정 투입률/M/M을 UI에서 조정하면 마진이 실시간 재계산되는 인터랙션 1건 포함(시연 포인트).
   - `/people` (임직원 투입 현황): 직원별 투입률 막대(프로젝트 배정 합산) + 벤치/과투입 표시.

4. **신호등·포맷 유틸 공통화**: 금액(억/만원 축약)·퍼센트·마진 신호등 색상을 `src/lib/format.ts`로 공통화해 3화면이 동일 규칙을 쓴다.

5. **예시 데이터 현실성**: 등급 4단계(초/중/고/특급), 표준원가·청구단가 플레이스홀더, 프로젝트 3~4건(마진 양호 🟢 2건 + 저마진 🔴 1건으로 발표 스토리 성립), 직원 6~8명, 배정으로 마진 숫자가 일관되게 떨어지도록 값 검산. 고객사는 중립 익명(A제조·B금융 등)으로 표기.

6. **발표 보조**: README 또는 `docs/`에 데모 시나리오(화면 순서·클릭 흐름·예상 질문 대응)를 1페이지로 정리(계획 범위에는 화면 구현까지, 시나리오 문서는 선택).

## Verification

- `npm run dev` 후 브라우저에서 3개 라우트(`/`, `/project/[code]`, `/people`)가 모두 렌더링된다.
- 화면①에서 저마진 프로젝트가 🔴로, 양호 프로젝트가 🟢로 구분 표시되고 전사 합계 행이 나온다.
- 화면②에서 배정 M/M(또는 투입률)을 조정하면 마진·마진율 숫자가 즉시 갱신된다(하드코딩이 아님을 시연).
- `npm run test`(vitest)에서 `pnl.ts` 단위 테스트가 통과한다 — 최소: 단일 배정 원가 = 등급원가×M/M, 프로젝트 마진 = 수주−배정원가합, 마진율 = 마진/수주.
- `npm run build`(adapter-static)가 에러 없이 정적 산출물을 생성한다 → 백엔드/DB 없이 배포 가능함이 증명된다.
- 목업 데이터의 마진 숫자가 손으로 검산한 값과 일치한다(예: 수주 4.8억 − 배정원가 2.61억 = 마진 2.19억, 45.6%).
